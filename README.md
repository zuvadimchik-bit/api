# Система автоматической оценки загрузки грузового транспорта (Почта России)

MVP программного комплекса компьютерного зрения для автоматического определения процента заполнения кузова автомобиля по фотографиям, сохранения истории рейсов в реляционной базе данных и интеграции во внешние контуры логистики через XML API.

---

## 1. Решаемая задача и бизнес-эффект
Ручной контроль загрузки грузового транспорта отнимает время операторов сортировочных центров и приводит к ошибкам учёта. Сервис решает следующие задачи:
* **Автоматический расчёт загрузки**: мгновенный прогноз заполненности кузова от `0.0%` до `100.0%` по фотографии.
* **Учёт и привязка к рейсу**: фиксация результата за уникальным `shipment_id` с возможностью последующего аудита.
* **Выявление недогруза**: сокращение пробега полупустых автомобилей и оптимизация вместимости подвижного состава.

---

## 2. Архитектура ML-решения

* **Базовая модель (Backbone)**: сверточная нейросеть `EfficientNet-B0` (предобученная на ImageNet).
* **Разрешение входа**: 288×288 пикселей. Обеспечивает баланс между видимостью мелких коробок/мешков в глубине кузова и скоростью обработки на CPU.
* **Регрессионная голова**: Dropout (0.2) + Linear(1280 → 1) + Sigmoid с масштабированием на диапазон `[0, 100]`.
* **Аугментация данных**: случайный горизонтальный флип (`p=0.5`), фотометрические искажения `ColorJitter(brightness=0.25, contrast=0.25)` для устойчивости к тусклому складскому освещению и вспышкам.
* **Стратегия валидации**: 5-Fold `GroupKFold` по идентификаторам визуального сходства (`group_id`). Исключает утечку схожих ракурсов одного автомобиля между обучающей и валидационной выборками.
* **Инференс для сабмишна**: ансамбль из 5 моделей фолдов + Test-Time Augmentation (горизонтальное зеркалирование) + калибровка краевых значений (`<= 3.5% → 0.0%`, `>= 96.5% → 100.0%`).

### Метрики локальной валидации (OOF — Out-Of-Fold по всем 716 фото):
* **MAE (основная метрика)**: **7.22 п.п.** *(лучший единичный фолд: 5.73 п.п.)*
* **Точность в пределах целевого допуска (ошибка ≤ 10 п.п.)**: **75.6%**

5. Воспроизводимость: Обучение и сабмишн


Обучение моделей с нуля:


```python train.py```




Скрипт фиксирует генераторы случайных чисел (seed=42), обучает 5 фолдов по 15 эпох с оптимизатором AdamW и планировщиком CosineAnnealingLR, сохраняет веса каждого фолда best_model_fold{0..4}.pth и выводит итоговый честный OOF-скор.



Формирование итогового submission.csv:


text ```
python make_submission.py
python check_sub.py ```





Скрипт находит все сохранённые веса фолдов, усредняет их предсказания с учётом TTA и формирует файл из 307 строк строго по формату ТЗ.



Регламент дообучения на новых данных:




- Поместите новые фотографии в директорию data/train/images/.


- Добавьте в data/train/train.csv строки с новыми image_id и подтверждёнными значениями load_pct.


- Добавьте соответствующие связки в data/train/train_groups.csv (если новые фото принадлежат одной серии/автомобилю — укажите общий group_id).


- Повторно запустите python train.py. Благодаря проверке локальных рекордов (score_foldX.txt), чекпоинты обновятся только в том случае, если качество на валидации станет выше.






6. Спецификация XML API



Сервер реализован на базе асинхронного фреймворка FastAPI. Все ответы возвращаются со строгим заголовком Content-Type: application/xml.



Запуск сервиса:


```uvicorn app:app --host 0.0.0.0 --port 8000```





Эндпоинт 1: Расчёт и сохранение загрузки







Метод: ```POST```








URL: ```/api/v1/predict```








Формат данных: ```multipart/form-data```








Параметры:





```shipment_id``` (string, обязательный) — идентификатор перевозки / путевого листа.


```file``` (binary file, обязательный) — изображение кузова (JPEG/PNG).









Поведение при повторном обращении: если передан уже существующий ```shipment_id```, данные рейса в базе SQLite обновляются новыми расчётами и актуальным timestamp (```INSERT OR REPLACE```).







Успешный ответ (200 OK):

```
<?xml version="1.0" encoding="UTF-8" ?>
<response>
    <status>success</status>
    <shipment_id>TRUCK_777</shipment_id>
    <load_pct>84.5</load_pct>
    <timestamp>2026-09-19T06:15:30.123456</timestamp>
</response>
```




Эндпоинт 2: Получение сохранённой оценки по рейсу




Метод: ```GET```


URL: ```/api/v1/shipment/{shipment_id}```




Успешный ответ (200 OK):

```
<?xml version="1.0" encoding="UTF-8" ?>
<response>
    <status>success</status>
    <shipment_id>TRUCK_777</shipment_id>
    <load_pct>84.5</load_pct>
    <timestamp>2026-09-19T06:15:30.123456</timestamp>
</response>
```




Коды ответов и обработка ошибок: 

- 400 Bad Request	Пустой или отсутствующий shipment_id	```<response><status>error</status><message>Номер перевозки не может быть пустым</message></response>```
- 404 Not Found	Перевозка не найдена в базе	```<response><status>error</status><message>Перевозка TRUCK_999 не найдена</message></response>```
- 422 Unprocessable	Повреждённый или не являющийся изображением файл	```<response><status>error</status><message>Некорректный или повреждённый файл изображения</message></response>```
- 500 Server Error	Внутренняя непредвиденная ошибка инференса	```<response><status>error</status><message>Ошибка сервера: ...</message></response>```




7. Демонстрационный веб-интерфейс (Streamlit)



Для визуального тестирования экспертами и операторами разработан веб-интерфейс.





- Убедитесь, что сервер API запущен (python app.py или команда uvicorn).


- В отдельном окне терминала выполните:




```streamlit run streamlit_app.py```





Сервер откроется по адресу http://localhost:8501. В интерфейсе доступны:



- Загрузка изображения кузова с предпросмотром.


- Расчёт процента заполнения и визуальный индикатор (прогресс-бар).


- Логистический статус рейса (Критический недогруз / Оптимально / Полная загрузка).


- Вкладка быстрого поиска по номеру рейса из базы данных.


- Отображение сырого ответа XML API.
